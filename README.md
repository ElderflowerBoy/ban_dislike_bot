# Ban Dislike Bot

Telegram-бот для групп и супергрупп. Он считает уникальные персональные реакции 👎 на сообщении и после достижения настроенного порога:

1. проверяет, что автор не является владельцем или администратором группы;
2. блокирует автора и удаляет сообщение;
3. показывает ephemeral-уведомление участнику, чей 👎 завершил набор порога.

По умолчанию автомодерация выключена, а порог равен 10 уникальным 👎. Настройки, статистика участников и незавершённые операции сохраняются в SQLite и переживают перезапуск приложения. Встроенный фильтр каналов блокирует каналы с `VPN`/`ВПН`/`PROXY`/`ПРОКСИ` в названии, а опциональный русскоязычный антиспам ставит один 👎 подозрительным сообщениям, включая рекламные связки VPN с бесплатным доступом к Telegram/TikTok/YouTube.

## Требования

- Go 1.26 или новее;
- токен бота от [@BotFather](https://t.me/BotFather);
- бот добавлен в группу как администратор с правами:
  - блокировать участников;
  - удалять сообщения.

Telegram присылает события реакций только администраторам. Бот запрашивает персональные `message_reaction` и события `chat_member`; агрегированные `message_reaction_count` намеренно не используются для наказаний.

## Запуск

```bash
go build -o ban-dislike-bot ./cmd/ban-dislike-bot
TELEGRAM_BOT_TOKEN=123456:secret ./ban-dislike-bot
```

Переменные окружения:

| Переменная | Обязательна | Значение по умолчанию |
|---|---:|---|
| `TELEGRAM_BOT_TOKEN` | да | — |
| `DB_PATH` | нет | `./data/bot.db` |
| `LOG_LEVEL` | нет | `info` (`debug`, `info`, `warn`, `error`) |
| `SPAM_FILTER_ENABLED` | нет | `false` |
| `SPAM_SCORE_THRESHOLD` | нет | `0.95` (от `0.5` до `1`) |

Приложение использует long polling, поэтому ему не нужен публичный HTTP-адрес. Запускайте только один экземпляр с одним файлом SQLite и одним токеном.

## Команды

- `/help` — справка;
- `/status` — состояние, порог и достаточность прав;
- `/set_threshold <1..1000>` — новый порог;
- `/enable` — проверить права и включить автомодерацию;
- `/disable` — выключить автомодерацию без удаления данных.

Изменять настройки могут только владелец и администраторы группы. После добавления бота настройте порог и выполните `/enable`.

## Антиспам

Фильтр каналов работает во всех чатах с включённой автомодерацией. Если сообщение отправлено непосредственно от имени канала, название и username которого содержат `VPN`, `ВПН`, `PROXY` или `ПРОКСИ`, бот блокирует этот sender-chat и удаляет сообщение. Для пересланной публикации бот удаляет сообщение, но не блокирует переславшего пользователя. Пересылки администраторов, анонимные администраторы и автоматические публикации связанного канала исключены. Текстовый фильтр также учитывает объявления, где VPN/прокси продвигается как бесплатный доступ к нескольким популярным сервисам.

Антиспам включается для процесса через `SPAM_FILTER_ENABLED=true` и работает только в чатах, где администратор выполнил `/enable`. Он использует pure Go байесовский классификатор, обученный на встроенных русскоязычных примерах, и дополнительные независимые признаки: ссылки, призывы написать в личку, денежные суммы и характерные рекламные обещания.

Бот ставит 👎 только при достижении `SPAM_SCORE_THRESHOLD` и наличии как минимум двух независимых признаков. Этот 👎 считается одним голосом, но не может запустить наказание без хотя бы одного человеческого голоса. Команды, сообщения администраторов и сообщения от имени каналов фильтром не помечаются. Бессрочная блокировка по-прежнему выполняется только после достижения общего порога 👎.

Тексты сообщений, после которых пользователь был действительно заблокирован, сохраняются в SQLite как подтверждённые спам-примеры. При запуске они загружаются в байесовский классификатор, а новые примеры добавляются в его кеш сразу после модерации. Значимые слова становятся отдельным обученным признаком только после появления минимум в трёх подтверждённых сообщениях и всё равно требуют ещё одного независимого признака, например ссылки. Сообщения, отмеченные только самим фильтром, в обучение не попадают — это предотвращает обучение на собственных ошибках бота.

Встроенная выборка является консервативным начальным набором, а не универсальной моделью. Перед включением в новом сообществе рекомендуется проверить характерные сообщения этого чата и при необходимости поднять порог ближе к `1`.

## Ограничения MVP

- отслеживаются только сообщения, которые бот получил и сохранил после начала работы в группе; получить автора более старого сообщения через Bot API нельзя;
- сообщения от имени канала с VPN/ВПН/PROXY/ПРОКСИ в названии блокируются отдельным фильтром; сообщения от имени группы и анонимного администратора игнорируются;
- порог считается отдельно для каждого сообщения;
- снятие 👎 уменьшает счётчик, но не отменяет уже выполненную блокировку;
- учитываются уникальные персональные 👎 от всех участников сразу; собственный голос автора за своё сообщение не считается;
- бот продолжает сохранять время появления, число сообщений и состояние участников для статистики, но эти данные пока не влияют на подсчёт голосов и порог;
- агрегированные `message_reaction_count` не запускают наказание, поскольку не содержат личности голосующих;
- администраторы защищены от автоматической блокировки, их актуальный статус проверяется непосредственно перед наказанием;
- в супергруппах Telegram может удалить и другие сообщения заблокированного пользователя при выполнении бана.

## Разработка

```bash
make verify
make test-race
make lint
```

Тесты покрывают дедупликацию Telegram-обновлений, статистику участников, уникальность голосов, единственную постановку наказания в очередь, сохранение SQLite, защиту администратора и повторные попытки при ошибках Telegram.

При первом `make lint` автоматически устанавливается закреплённая версия `golangci-lint` в локальный каталог `bin/`. Linux-бинарник для VPS собирается командой:

```bash
make build-linux            # amd64
make build-linux GOARCH=arm64
```

## CI/CD и VPS

Workflow `.github/workflows/ci-deploy.yml` проверяет каждый pull request и push в `main`. После успешных проверок push в `main` разворачивается в GitHub Environment `production` на VPS через SSH.

Первоначальная настройка systemd, секретов GitHub, SSH host key и каталогов описана в [deploy/README.md](deploy/README.md). Telegram-токен и файл SQLite остаются только на VPS и не передаются при каждом деплое.
